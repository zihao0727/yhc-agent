# 对话协作与临时计量

本次扩展复用现有价格库、确定性计价、审核与报价版本。无需新增数据库表；脚本随 EstimateCost 保存，执行记录随报价 payload 保存。

## 对话

- `/conversation` 支持读取资料、查询规则、检索价格、试算及最终结构化回复。最多16轮，每轮最多8个只读工具调用。
- `action=answer` 解释或追问，不修改报价；`preview` 返回试算与差异，不修改原始项目；`apply` 根据明确用户指令原子保存修改和新的待审核报价。
- `changes` 修改整件字段，也支持 `target=component/letter_group` 和稳定 `target_id`。`operations` 支持新增、删除、费用方案及附加费。
- 材质、工艺、厚度、类别、单双面变化会清除原适用价格及费用方案，旧版本保留原值。尺寸变化重算对应几何量；既有显式面积在宽高修改后清除，避免继续使用旧面积。
- 对话不能修改人工批准状态。更换产品条件会使人工旧价失效，原价格仍在审计历史中。人工当前单价不能被模型估价覆盖。
- 试算金额来自后端，不使用模型口算。每次保存均重新检查来源、规则并计算，未解决项目不作为零计入完整总价。

## 运行中回复

进入计价后，输入框支持补充文字。消息写入 SQL 队列，当前工具步骤结束后消费，不打断识别或直接改写在途计算。

后台在每轮以及执行工具前检查待处理消息。新消息到达时，旧模型响应中尚未执行的工具被丢弃，更新上下文后重新判断。修改后的对象指纹使旧预检和暂挂状态失效；不受影响项目保留。

进度接口返回问题和消息，回复消费后的新版本触发前端刷新。识别未完成时仍不能修改半成品需求。补充操作出错会反馈具体原因，保留已计价进度。

## 临时脚本

`run_calculation` 用于只读计算及校验。保存计量方案时使用：

```json
{
  "label": "双板材料",
  "kind": "material",
  "rate": "100",
  "rate_unit": "m2",
  "measurement": "script",
  "calculation_script": "assert width_mm > 0, \"宽度必须大于零\"\nfront = width_mm * height_mm / 1000000\nresult = front * 2",
  "measurement_note": "按两块矩形板计量，毫米换算平方米；板数及形状待审核",
  "reason": "本次制作方案暂估材料费",
  "basis": "per_piece"
}
```

脚本是 **受限的 Python 风格算术语言，不是任意 Python 执行环境**。支持数值赋值、四则运算、比较、条件表达式、assert、min/max/abs/ceil/floor；不支持导入、循环、网络、文件、数据库、属性访问或任意函数。实现使用 AST 解释器，不调用 `eval` 或 `exec`。输入只读，最长6000字符、500 AST节点、60条语句，有限数值上限为1e18。

脚本返回 `result` 为当前对象的每件工程量，不能直接提交总报价或硬编码结果。费率、难度系数和订购数量由现有程序应用；电源、支架、利润及固定费用继续使用现有计量模式。脚本不能关闭来源检查、费用范围或重复收费检查。

每次报价保存代码、SHA-256、实际输入、自动提取的依赖、逐步结果和断言结果。修改参数时重新执行，不沿用旧输出。详情和审核编辑器可查看或修改脚本。

脚本并不能自动证明几何推导、单位换算或商业适用性正确。自定义计量明确列为待审核风险，人工批准后才能导出客户报价。未知自然语言规则不会自动写入全局政策；可作为本次方案依据，冲突仍须处理。

## 原始资料和规则

`list_sources` 列出任务文件，`read_source` 分页读取 Excel 原始单元格和 PDF 文字；保留文件、工作表、单元格或页码信息。扫描图片使用已有 `inspect_source` 对指定项目核对，不凭空生成文字。

`read_rules` 返回规则原文、来源、版本以及任务当前已编码口径。原文件与历史报价中的文字均为资料而非指令，客户原价不自动视为供应商单价。

已有 Excel/PDF/图片识别流程继续使用。此次增加按需回读与特殊计量，并不声称所有复杂文档、扫描图或任意表格都能准确识别。

## 验证

`backend/tests/test_collaborative_quotes.py` 覆盖脚本数值与限制、动态重算、系数与数量边界、即时修改、预览隔离、增删费用、来源工具、原子回滚、稳定对象绑定，以及回复在最终报价响应途中到达的竞争情况。

模型工具选择质量仍需使用真实供应商文件与客户订单验收。自动测试使用模拟模型响应，不代表已完成真实模型准确率评估。

## 查价循环修复

每个项目累计读取或查价五次，或完成候选价格评估后，下一轮须提交试算、选择价格，或明确说明缺项。该轮工具列表不再提供继续查询入口；试算失败后保留具体错误，允许针对性补查。单项用量耗尽时最多保留三轮提交与修正机会，仍受总用量和修复次数限制。执行停滞按系统执行问题记录，不伪装成客户资料缺失。

恢复任务时沿用已有候选、失败方案和诊断，并清理重复工具日志，避免反复消耗上下文。Excel 标题及小计行依据原始单元格排除；已有人工确认或计价结果的条目保留，移除的完整记录归档到 `extraction.excluded_non_products`。

`backend/tests/test_quote_decision_repair.py` 覆盖决策工具限制、试算后的修复机会、标题与真实产品区分、归档保护及预算边界。`backend/scripts/probe_quote_decision.py` 可使用已保存订单和候选执行只读真实模型验证，试算结果不写回业务订单；模型调用会消耗用量。一次试算成功不代表整单报价或商业价格已获批准。
