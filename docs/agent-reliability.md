# 报价流程修复与验收

2026-10-15，本轮围绕资料覆盖、补充表单、计价记忆、工具可用性、文件适配和并发调度修复。

## 行为变化

1. 清单与图纸混合上传时，图纸中的观察不会因已有清单而被整体隐藏。同一成品应合并，参考视图明确排除，另行订购产品确认后转为需求。尚未关联的图纸保留来源问题，阻止误报整单完成。
2. 同一产品的不同问题分别绑定补充字段。缺尺寸、缺单价、系统错误不会互相混入；相同文字但不同原因的事项仍分开显示。
3. 补充表单可读取旧版已保存或失败方案中的拟建部件、字组及假设参数。暂估值保留标识，不当作原始事实。
4. 不再按累计五次读取收走调查工具。新来源、新核图和有效脚本结果允许继续推进；重复或空查询会提示提交方案。定向读原件、查规则、核图及修脚本仍可使用。重复调用、无进展、时间及配置用量限制继续生效。
5. 用户修改数量、尺寸等参数后，保留可兼容的候选和未完成费用方案，移除被用户覆盖的参数及失效派生量，重新校验。按稳定对象编号复用已补充部件，其他待建部件继续保留。产品身份、原始来源或规则版本变化时丢弃不兼容记忆。旧运行在下一次用户修改前补存输入快照，兼容恢复。
6. 新增CSV、TSV、TXT、DOCX及旧XLS。保留原件，另建可追溯的规范化来源与预览，脚本可同时读取两者。文件边界和容器约束见[file-workspace.md](file-workspace.md)。
7. 并发请求释放名额后补发下一项，无需等同批最慢项目。停止、分片和用量边界会先收齐已发请求并记录用量；过期输入的响应不得修改需求。

## 验证入口

- `backend/tests/test_source_agent.py`、`test_quote_presentation.py`：混合来源、未解决图纸、旧方案表单。
- `backend/tests/test_agent_work_state.py`、`test_pricing_proposals.py`：证据进展、参数补充后修复、旧运行恢复、部件共存和金额重算。
- `backend/tests/test_customer_documents.py`、`test_file_workspace.py`：文件转换、来源、预览、重新解析、校验和以及真实Docker执行。
- `backend/tests/test_parallel_pricing.py`、`test_quote_decision_repair.py`：并发补位、过期响应、停止、重复操作与额度保护。
- `frontend/tests/quote-workspace.test.mjs`：同产品多事项字段隔离。
- `scripts/smoke-workbench.cjs`：模拟接口下补充保存、继续报价和桌面/手机交互；`scripts/smoke-workbench-live.cjs`：现有订单只读验收。

本机验收结果：启用真实Docker集成的后端全量回归1047项通过、3项跳过；随后针对空首列和旧索引预填的最终代码，79项专项回归全部通过。前端49项测试通过，生产构建成功，仍有现有打包体积提示。浏览器模拟验收和订单21的只读桌面/手机验收均通过，无页面运行错误；未调用真实付费模型重新报价。API已在本地8002端口重启，前端使用5173端口。

## 使用与边界

刷新页面后使用新版显示；已有暂停订单点击“继续报价”重新处理。不会批量替用户恢复订单或自动批准旧报价。

这些修复增强“读资料、写方案或脚本、校验、补充后继续”的能力。缺少可信价格、数量或业务范围时仍须明确提问。自动化测试和容器联调不代表任意文件均能无遗漏计价，也不等于真实模型已为现有订单重新完成报价。
