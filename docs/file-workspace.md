# 文件处理与校验工作区

工作区接入报价工具、对话工具和识别校验失败后的恢复循环。每个订单、每次执行都有独立目录，位于客户文件存储目录的 `_workspaces/<job_id>/<artifact_id>`。原始上传文件不变，脚本仅接触本次选择的订单原件副本。

## 执行流程

1. 标准 Excel 默认先由程序读取名称、数量、单位、专用尺寸列及原文，并执行来源覆盖和数量校验；只把无法确定用途或行归属的页面交给模型。PDF、图片继续使用原有识别。模型可调用 `list_file_workspace` 检查运行环境、输入输出约定、历史记录和适配器。
2. 复杂布局、校验失败或需交叉检查时，调用 `run_file_script`。Python 可使用标准库、openpyxl、xlrd、pandas、pypdf、Pillow、python-docx 和 defusedxml；不能联网安装依赖。
3. `/input/manifest.json` 包含原件路径、文件ID、哈希以及本次页面原文。`path`始终指向原件；CSV、TSV、TXT、DOCX、XLS另提供`normalized_path`，可用openpyxl读取。来源视图的`origin`保留原记录、原工作表行号或Word段落/表格位置。读取原件需使用manifest路径，临时文件写 `/work`，最终 JSON 写 `/work/result.json`。
4. 输出可包含 `observations` 和 `checks`，它们属于未经批准的观察。要提交提取结果，使用 `extraction` 对象，结构为现有 `ExtractionResult`；逐行提供真实文件、页码和单元格/原文证据。
5. 主程序独立执行来源、数量、尺寸及来源覆盖校验，检查重复项、缺数量、恢复的遗漏行和被纠正的数值。脚本里的“通过”声明不作为校验依据。
6. 错误和诊断返回模型。可修改脚本，以 `previous_artifact` 关联上次记录重试。识别恢复在原有来源与结构校验通过后接受规范化结果；无法确认的业务参数、校正值及遗漏提示保留为待复核项，不能当成已确认事实。重复来源结果不接受。计价和对话工具不直接覆盖需求，仍须通过原有修改、计价及审核流程。
7. 执行记录含代码、代码哈希、输入文件哈希、环境镜像ID、输出和诊断。容器结束后临时文件丢弃，原件副本删除；脚本、manifest 和 JSON 结果保留。需要保留的中间数据须放入结果 JSON，当前不导出任意二进制中间文件。

## 隔离与安装

需要 Docker Linux 引擎，执行 `scripts/build-file-worker.ps1` 构建镜像。未就绪时工具返回 `service_unavailable`，不会在宿主机执行生成的 Python。

执行容器关闭网络、以非 root 用户运行，根文件系统和输入只读，无额外 capabilities，无数据库凭据、API Key、宿主代码目录或 Docker socket。临时空间、内存、进程数、CPU、输出和运行时间受限；取消或超时后移除容器。隔离依赖 Docker 本身正常运行，不是 Python 语言级防护。

| 配置 | 默认值 |
| --- | --- |
| FILE_WORKSPACE_ENABLED | true |
| FILE_WORKSPACE_IMAGE | firefly-file-worker:1 |
| FILE_WORKSPACE_TIMEOUT | 45秒 |
| FILE_WORKSPACE_MEMORY_MB | 512 |

无网络限制针对脚本容器；首次构建镜像需要下载基础镜像和依赖。主要依赖版本固定在 Dockerfile 中。

## 适配器复用

只有通过独立校验的提取脚本可保存为候选。Excel 以识别出的表头和列映射匹配结构；其他格式先保守地匹配原文件哈希。每次复用都重新执行、重新校验，绝不搬用上一次的数量或价格。同一脚本与结构在两组不同原文件哈希上通过校验后标记 `verified`。这代表有限样本验证，不代表所有同类文件都适用，更不代表商业价格已批准。

API：`GET /api/jobs/{job_id}/file-workspace` 查看环境和最近执行；`GET /api/jobs/{job_id}/file-workspace/{artifact_id}?offset=0` 分页查看本订单结果。界面“资料与计价核查”中可查看执行状态和适配器。

读取接口和 `read_workspace_artifact` 工具支持 `section=script` 取回归档代码，以便对话压缩或恢复任务后继续修改脚本。

## 当前边界

- `EXCEL_NATIVE_FIRST=true` 默认开启。普通报价指令且无既有需求修改时使用快速路径；新的业务指令或既有编辑仍走语义处理，避免忽略客户修改。
- 快速读取不会猜测复杂描述中每个数字的用途。工艺原文、单元格和图纸锚点保留，计价时按对象解析，存在歧义再核对来源；图纸未核对不代表尺寸已确认。
- 相同文件按内容哈希及解析版本复用基础事实，并重新绑定当前文件ID；不缓存客户编辑或报价。已完成页面和数据库中已验证的行批次继续复用，分拆重试的细批次优先。
- 提取速度不等于整单计价速度。复杂页、图纸核对、计价规则匹配及缺失业务参数仍可能需要模型或用户处理。

- 上传支持XLSX、XLS、CSV、TSV、TXT、DOCX、PDF、JPG、PNG、WebP。原件及校验和保留，转换文件单独保存并校验，不执行上传公式。CSV支持UTF-8、UTF-16 BOM、GB18030及带引号的多行字段；数字编号前导零保留。
- Word来源页是段落/表格分段，不是打印页。常见内嵌图片进入核图流程；图片缺失会留下未解决来源，不因模型声明“已看过”而解除。复杂Word版式与特殊对象不保证还原。旧XLS读取可见单元格及公式缓存值，图形对象须另附PDF或图片核对。
- 不自动接受未知格式、宏文件、损坏或加密文件。工作区处理的是已被系统接收的原件。
- 原生解析直接拒绝上传的文件尚不能进入 Agent 工作区；恢复循环处理的是已入库资料的识别或校验失败。
- PDF/图片默认增加独立区域巡视与漏项重读，详见 [PDF、图片与多文件报价识别](visual-recognition.md)；视觉核查仍不能保证任意图纸无遗漏。无可核实文字的图像观察须由核图工具核对，脚本不得伪造证据。
- 关键业务事实缺失时仍需用户补充。算出数值不等于得到可靠供应商价格；人工确认、价格依据和报价审核约束继续生效。
- 工作区允许通用 Python；没有授予修改宿主业务程序、数据库或全局规则的能力。

## 验证

`backend/tests/test_native_excel.py` 验证默认路径不调用模型、明确尺寸换算、工程量与件数分离、跨订单缓存来源重绑定、复杂页回退、断点恢复、旧批次保留，以及后台进度。

2026-10-13 对 `0923-广州标识(1).xlsx` 做只读提取验证：加入明确待定费用尾行识别后，6页85项均可直接提取，原序号1至85完整连续，程序提取约0.13秒、模型调用0次。安装和发票待定保留来源并列入费用确认问题，计价上下文和报价审核仍能看到，不默认免费或已包含；金额、公式或额外说明复杂的尾行继续交给语义识别。这不是上传解析、整份语义理解或整单计价的耗时。

`AGENT_MAX_TOTAL_TOKENS=0` 和 `AGENT_LINE_MAX_TOKENS=0` 分别关闭整单和单项模型用量上限，默认均为0；用量继续记录。重复失败、无进展和处理时间检查继续生效。关闭单项用量限制后，同一运行内有明确额度触发记录的暂挂项目会重新尝试一次，保留已完成方案及错误诊断。

`backend/tests/test_file_workspace.py` 覆盖订单隔离、来源伪造、数量冲突、重复项、脚本修复记录、适配器再次校验、识别恢复接入及运行环境不可用时禁止宿主执行。

构建镜像后设置 `FIREFLY_SANDBOX_INTEGRATION=1`，运行该测试文件及`backend/tests/test_customer_documents.py`，可实际验证容器读取XLSX、CSV、DOCX、XLS原件与转换来源，以及原件只读、根目录不可写、无网络、无凭据和超时终止。

`python -m scripts.probe_file_workspace --job <id> --page 1 --turns 3` 可做有轮数上限的真实模型验收。它会消耗模型用量并保存工作区记录，不更新业务需求或报价；`--resume-artifact <id>` 可继续既有脚本。

2026-10-13 对订单17的第一页做过真实模型与容器联调：在输出文件遗漏和来源结构错误后继续修正，生成13条记录；主程序拦截了将500米工程量当作500件的输出，保留原工程量并标记待复核。该页另有一个未明确用途的原文行。此结果是资料处理验证，未宣称整单报价完成或完全自动识别成功。
