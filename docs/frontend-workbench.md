# 报价工作台

主工作区分为报价结果、待补充、沟通记录。报价会话列表是日常操作的唯一侧栏，成本资料、规则、来源文件和审计记录从“资料管理”进入。

## 补充信息

- 待补充问题按资料、价格和系统问题区分，同一组问题保留原始项目序号及全部适用项目。
- 明确的整件字段可直接填写，勾选适用项目后保存；部件和字组按名称展示宽高、每套部件数量或每件字数，补充只更新对应对象。
- 原文或明确来源的已知参数预填；计算推导或假设参数仅作为待确认提示。未修改的预填值不作为新的人工事实提交。
- 正在报价时可提前填写字段、说明和选择附件，草稿保留；当前执行结束后可保存补充并继续报价。
- 缺少参数显示具体部件和业务字段，原始程序字段及诊断收纳在折叠的技术详情中。
- 多项目问题展开后按项目展示表单，部件宽、高、数量在桌面并排、手机逐行。部件名称采用简写，完整描述保留在“部件说明”中；其他整件字段从“补充其他信息”展开。
- “保存补充”保存字段或生成文字修改预览；“保存补充并继续报价”在保存后继续处理。文字产生的修改方案仍需逐项确认。
- 文本草稿按订单保存在浏览器会话存储中，切换页面、订单或刷新可恢复。附件在组件存续期间按订单保留；刷新后需重新选择本地文件。
- 问题变化后，旧草稿有单独恢复入口，可移入整单补充再提交。
- 字段校验或保存失败保留未提交内容。字段已保存但后续模型失败时，只保留尚未处理的说明或附件。
- 附件追加沿用现有重新识别流程，提交前明确确认其影响；已上传成功的附件在识别重试时不会再次上传。
- 未完成识别的订单可继续整理，同时保留信息草稿。

字段更新保留其他项目、来源、费用方案及历史版本；尺寸变化清除旧面积和旧费用校对金额，材质/工艺变化清除过期价格依据。人工成品单价必须填写依据和包含范围，补充不会自动批准报价。

## 查看结果

- 未生成整单报价时展示实时计价结果，已算出项目的单价、金额和费用明细随进度更新；未算出项目显示待计价。
- 规格优先展示计价采用的尺寸或部件尺寸；无法确定整件尺寸时展示原文规格，保留原始数量单位。
- 已生成报价集中显示序号、项目、规格、数量、成品单价、金额和状态。
- 缺少金额不显示为零；未完成报价显示已计价小计，失效版本明确标为历史金额。
- 项目明细分费用组成、采用参数、来源与说明。脚本、校验及诊断位于折叠的执行记录。
- 未计价明细优先展示实际缺少的资料或价格依据，去掉重复的空价格行；费用范围、规则提醒在“计价说明”中折叠，原始诊断仍可查看。
- 审核和客户导出沿用原有校验。客户导出仅对已批准且有效的报价开放。
- 历史版本和本版变化可以在结果页面查看。

## 验证

前端：`npm test`、`npm run build`。

浏览器验收（需要可用的 Playwright 和 Chrome）：

- `node scripts/smoke-workbench.cjs`：隔离的模拟 API，验证批量范围、草稿恢复、保存失败、继续计价、文字确认、桌面/平板/手机和夜间模式。
- `node scripts/smoke-live-quote-display.cjs`：隔离模拟 API，验证实时及零元价格、部件规格、原文单位、易懂问题、预填和假设区分、处理中草稿及精确部件保存。
- `node scripts/smoke-workbench-live.cjs`：仅发送 GET，读取真实订单检查页面，不重新计价、不修改业务数据。
- `node scripts/smoke-quote-layout.cjs`：仅发送 GET，检查真实订单的分项目表单、明细提示、说明折叠、桌面/平板/手机/窄屏及夜间背景，默认订单 21，可用 `JOB_ID` 指定订单。
- `node scripts/smoke-ui.cjs`：管理界面、查询、历史、来源及移动端回归。

默认地址为 `http://127.0.0.1:5173`；工作台脚本可通过 `UI_URL` 指向其他开发地址。验收截图位于 `.runtime/screenshots/workbench-*.png`。
