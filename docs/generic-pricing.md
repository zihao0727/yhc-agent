# 通用报价机制与维护

## 目标与边界

本机制按工程量和费用对象组织报价，不绑定客户、产品名称、工作表列位或某张清单。永久优化是可扩展、可校验、可回归的计算契约，不是承诺任何未知产品都能自动得到可靠供应商价格。

AI负责理解资料、选择策略、寻找单价依据和提出审核方案；程序负责类型、来源、单位、金额、重复计费与版本检查；管理员负责确认识别、适用范围和商业价格。资料中的指令只作为资料，不提升权限或执行。

已确认的业务规则仍使用 `2026-09-23.v1`：加工难度系数仅作用于加工/外加工，电源200元/台，楼顶支架250元/平方米，指定外加工才适用最低0.1平方米，运输、安装、税费、打包另列。未知范围与商业取整不擅自固化。

## 对象与策略

| 对象 | 计量来源 | 用量 |
| --- | --- | --- |
| 整件 `item` | 整件面积、长度、字组总计、工时或固定工程量 | 成品订单数量由程序统一相乘 |
| 字组 `letter_group` | 本组单字尺寸、单字计价长度及字符数 | 不借用其他字组尺寸 |
| 部件 `component` | 本部件尺寸、明确面积、长度或工时 | 使用 `quantity_per_item`，不默认缺失用量为1 |

`pricing_strategies.py` 提供逐字、面积、长度、件/套、部件组合、工序/工时六类策略。策略可以混合费用，分类不代替单位校验。新增产品通常只需整理对象和选择现有策略；确实新增计量逻辑时才扩展注册表、参数计算、校验及回归测试。

不同字组使用各自的参数补全与费用归属。`count_basis=characters` 时，字符数必须与非空白文字数相等，不能把英文词数当字母数。重复图形或编号使用明确的重复数量并保留证据。

异形、壳体部件必须给出明确面积或有依据的计量说明，不能无声地把包围框面积当展开用料。对部件外加工，先按每件成品的真实部件用量汇总面积，再应用显式选择的按件/整行最低面积口径；报价仍须核对供应商实际结算范围。

## 费用契约

新方案采用 `contract_version=2`。每项费用包括单价、单价单位、公式、费用类别、来源、对象、依据及按件/整单范围；自主估价必须提供 `expected_amount`，与程序复算结果一致才能保存。

常用部件计量公式：

| 单价单位 | 部件公式 |
| --- | --- |
| 平方米 | `=billable_area_m2` 或 `=area_m2*component_count` |
| 米 | `=billing_length_mm/1000*component_count` |
| 厘米 | `=billing_length_mm/10*component_count` |
| 件/套 | `=component_count` |
| 小时 | `=labor_hours*component_count` |

部件 `billable_area_m2` 已含部件用量，不能再乘一次。整件固定费用不因无关的单字尺寸缺失而阻塞。每件公式不能再乘订单数量；整单一次费用不随成品数量重复。

数学等价的乘除公式可接受，但禁止把按件单价乘厘米、在工程量中暗藏报价倍数或套用未经确认的最低面积。单价结构化依据金额和单位必须配对且与采用单价一致；这只保证单位一致，不证明供应商价格真实。

## 包含范围与重复费用

价格管理员可维护 `included_cost_kinds`，保存为价格的 `attributes.included_cost_kinds`；模型方案也可声明 `included_kinds`。包含范围对同一对象及整件包含的下级对象生效，调换费用顺序不能绕过检查，独立部件之间不误判为重复。

真实差价用 `adjusts_cost_index` 引用前置基准费用并解释调整原因。删除、排序费用会同步调整引用；仍被差价引用的基准费用不能直接删除。对象被费用、补全引用时不能直接删除，避免索引漂移到另一对象。

人工附加费与已声明包含范围、电源或支架项目冲突时会阻塞计价，必须核对，而不是叠加收费。历史价格缺少包含范围会提示审核，不猜测已含内容。

## 来源、补全与纠错

`fill` 只补空值/未知值，不覆盖已有事实。`correct` 必须携带 `previous_value`、纠错理由与来源；当前原值已变化或原始需求已人工确认时，不允许Agent纠正。

纠错只作用于计算视图，原始需求保持不变。审核清单记录对象路径、原值、采用值、采用方式和证据；客户导出使用已审核的计算结果，内部审核保留依据。

Excel文本纠错需命中原始单元格文字，并限于当前对象来源行；不能引用其他项目的数字。PDF文本纠错需命中该页文本层。数值必须出现在所引文字里。图片证据可验证文件/页码/单元格归属，但无法自动证明视觉读数准确，仍需人工复核。

整体尺寸、单字尺寸、板厚、壳深、间距和局部尺寸分别记录，局部标注不覆盖整件宽高。更新提取契约会使旧识别检查点失效，但不会擅自重新调用模型或重写已保存需求。

## 上传数量识别与恢复

`quantity` 仅表示正整数成品件数，不代表字数、部件用量或订单工程量。米、厘米、毫米、平方米等实际数量和单位换算后保存在 `source_measurements`，与件数分开；没有可靠件数时保留 `null`，不截断小数、不默认1件、不直接进入计价。

数量校验按来源处理：明确的Excel数量栏结合真实单位栏核验；图纸锚点的OCR标注按图片依据处理，即使模型漏写 `source=image`；PDF文本标注核对该页引用文字。表头与列位来自解析规划或实际表头，不绑定文件名、客户或固定地址。重复数字只能在已确认的项目行中消歧，不从其他行借数。原表工程量由实际单元格重建，不采用模型编造的数量/单位；图片视觉读数仍需人工复核。

局部语义问题（单位不是件数、标注不清、小数件数、模型件数与单元格不一致）保留该项目及其他字段，将数量依据标记 `rejected` 并记录具体原因、页码或单元格。若有独立的真实数量栏可以恢复件数；图纸与数量栏存在真实冲突时保持未知。`validation_status` 由程序复核，不信任模型自报 `verified`。工程量及数量疑点在需求编辑和报价明细中可查看。

局部数量疑问不触发整份资料失败或为同一疑问重新调用模型。跨文件/跨页/跨项目错引、不存在的单元格、畸形字段、截断响应仍按安全与完整性错误处理；持续失败显示字段/项目路径及单元格，不静默绕过校验。

成功批次保留拒绝的原始数量依据和工程量，重复校验不叠加同义冲突、不累加重复图纸、不重新请求成功批次。提取契约版本为3；旧版本检查点失效，已保存业务需求和报价不被自动改写，失败任务须在用户授权继续后重新处理。

新增回归集中在 `backend/tests/test_quantity_recovery.py`，覆盖混合单位、列位变动、小数、图纸/PDF标注、错误来源、完整上传、后台worker、多批合并和断点恢复。可对任意已存Excel清单的 `excel.json` 运行 `scripts/verify-quantity-source.py` 离线复验；该脚本模拟旧件数输出并校验恢复，不调用模型、不写SQL或原文件，不代表真实模型理解质量评估。

## 未计价处理

- `priced`：可计价。
- `priced_review`：可计价但暂估、纠错或存在审核提示。
- `customer_confirmation`：明确缺少客户资料，提出可回答问题。
- `administrator_pricing`：报价依据不足或待管理员核价。
- `execution_error`：运行受阻，由系统或管理员处理。
- `unresolved`：尚未形成可保存方案，不能默认归咎于客户。

缺失字段已存在时拒绝客户追问；先读取资料、分对象补全或有证据纠错。失败方案返回字段路径、诊断和修复契约。新候选或新诊断允许有限度修复继续，相同读取/搜索不能无限重置进度。

已计价金额参与小计；未知金额为null，整单未完成时总价为空，不能批准或正式客户导出。界面分开显示未计价项目数和合并问题类别数。

## 审核、版本与回归

自主单价缺少结构化依据、库价包含范围未知、用整件面积估多部件材料或同类暂估费率差异较大时显示风险。`QUOTE_ANOMALY_RATIO` 默认4，仅控制差异提示，不提供虚构市场价格边界。

旧方案默认v1，不自动迁移重算。新方案v2独立于业务规则版本；价格、需求或依赖版本改变会使已有报价失效。无需新增数据库表，因为契约及审核快照保存在现有JSON字段中。

修改通用逻辑至少运行全量后端测试、前端测试与构建，并运行浏览器验收。回归应覆盖字组、平板面积、贴膜长度、组合部件、件/套、工时、整单一次费、数量扰动、费用重排、重复包含、来源防伪、历史兼容及旧报价失效。

测试使用隔离数据库schema或浏览器模拟接口；不回填实际业务订单，不修改客户原始文件，不调用付费模型。真实模型的资料理解与市场单价准确率需另做授权后的代表性样本评估。
