# 萤火虫报价管理

## 报价可靠性

价格列表、Agent 和候选抽屉现共用检索；计量与工序覆盖绑定实际部件；系统错误、待核图、客户事实缺项和管理员缺价分开处理。授权后的等待项目按依赖变化恢复，前端显示后端当前已校验结果。共享契约、维护接口、独立 worker、运维与真实事故验收见 [报价可靠性与运维](docs/quotation-reliability.md)。

## 对话协作改进

现支持明确对话指令直接修改待审核草稿并重算，比较方案只读试算；可增删项目、修改费用和指定部件/字组。计价进行中可回复问题，后台在工具步骤之间应用补充，保留其他项目进度。新增原始资料回读、规则查询和受限算术脚本，特殊工程量可保存到费用方案，修改参数后自动重算，并保留代码、输入及校验记录。自然语言规则与脚本计算均不自动成为已批准政策。

详细边界、数据契约与验收说明见 [对话协作与临时计量](docs/collaborative-quoting.md)。

第一阶段提供 PostgreSQL 价格资料管理；第二阶段提供图片/PDF/XLSX 客户需求和真实工具调用 Agent Loop，自主查库、判断结果、换条件查询、生成报价草稿，保留人工核实及批准导出。新增 2026-09-23 现场规则的版本化计价口径。

资料整理默认由 AI 主导：主动阅读多份原件、放大区域、比对清单与图纸、纠正/合并/排除误项，
按页检查漏项，仅针对疑点回看原件。代码记录来源、断点和修改历史，不以图号或名称严格匹配决定业务归属。
金额计算及人工审批保留。配置、预算、兼容模式和验证边界见 [资料核对流程](docs/visual-recognition.md)。

- 后端：Python、FastAPI、SQLAlchemy、Alembic。
- 数据库：PostgreSQL 18。独立库 `firefly_pricing`，专用非超级用户 `firefly_pricing_app`。
- 已实现：价格增删改查、搜索筛选分页、规则原文管理、来源定位、版本历史、修改审计。
- 删除采用停用，保留来源及历史。编辑需要理由，过期版本提交返回 409。
- 第二阶段已实现：图片/PDF 上传与分页预览、DeepSeek 视觉接口、结构化需求校验、补充与重试、人工核实、价格候选、确定性金额计算、报价版本、批准和客户版 CSV 导出。

## 现场口径

新任务默认使用 `2026-09-23.v1`，迁移 `a923f1` 仅追加版本字段及扩展文件类型长度，不改写已有价格、需求及报价。历史任务维持 `legacy`；点击“采用现场口径”才升级，保留旧报价快照并使其过期，所有需求重新审核。每个报价保存规则快照。

- 字类单价：单字厘米 × 每件字符数 × 单价，再乘成品件数。不同尺寸通过字组分别计量；成品数量不等于字数。字类平方米计价汇总各字图纸面积；造型材料按明确图纸面积或宽高。
- A=3、B=2、C=1 仅应用于单列加工/外加工费用，不对材料、成品、电源、支架整体加倍。库内成品引用也需使用正确的字类/面积公式。双面、材料和工序已经包含的部分不重复加价。
- 电源暂按 200 元/台、约 3 平方米/台，逐字核算。默认人工台数；“逐字向上取整”须显式选定，笔画调整需要依据，Logo 单列复核。六字各 6.76 平方米按逐字向上取整为 18 台，不能以整行面积除以 3 后得出 14 台。
- 楼顶须单列支架制作，暂按图纸计价面积 × 250 元/平方米；不等于现场安装。人工电源/支架附加费也验证台数、面积、费率和件数。
- 外加工背胶 50、裁形 100、3M 胶 200 元/平方米，最低 0.1 平方米仅适用上述外加工，不是通用小面积加价。最低面积按每件还是整行未确认，小面积方案需显式选择暂定策略并接受审核。
- 排除物流、运输、现场安装、发票/税费、打包；系统拒绝将上述费用混入当前口径的费用方案及附加费，条款自动列示排除范围。
- 图纸明确标注优先于冲突的表格尺寸，保留原始证据及冲突提示。不推断壳体展开面积、材料损耗或通用小面积加价。
- 厘米及整单商业取整默认不执行；人工选定取整后保留原值、策略、调整额，逐行金额与总计可对账。会议矛盾示例不固化为政策：`19 × 22 × 4 = 1672`，`550 + 250 = 800`。

内部审核 CSV 可在批准前下载，含计算过程、原始资料、来源、费用依据和待确认事项；客户 CSV 仍须批准后导出。当前口径的客户文件不包含内部成本审核清单，两种文件均有“类型备注”和“工艺难度备注”。人工成品价优先，但必须说明包含范围并经审核。

也可在两个终端分别运行：

```powershell
# 后端，在 backend 目录
../.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# 前端，在 frontend 目录
npm.cmd run dev
```

## 表结构

- `product_categories`、`products`：分类与产品。
- `price_items`：当前价格，使用 Numeric，包含状态和乐观锁版本。
- `price_revisions`：每次价格变动的不可变业务快照。
- `pricing_rules`：产品相关规则、公共说明和钣金案例原文。
- `source_documents`：来源文件指纹、导入时间和导入报告。
- `source_records`：原工作表、行号及单元格内容。
- `change_logs`：操作人、原因、前后快照及时间。
- `alembic_version`：数据库结构迁移版本。

## 安全与后续

本阶段是单管理员、本机使用，不应直接对公网暴露。上线前需要 HTTPS、实名用户/角色权限、登录限流、备份恢复方案及密钥轮换。

“仅识别”不向模型发送报价库，不允许模型补造原文事实。Agent 模式经明确授权后向 DeepSeek 发送当前查询得到的候选报价数据及关联规则；允许生成明确标记、待审核的补全参数和费用估算，不允许伪造来源或人工确认状态。最终金额始终由程序计算。

## Agent 自动报价

1. “客户需求”首页现在为对话界面。配置 DeepSeek Key 后，直接输入需求，或附加图片/PDF/XLSX；勾选外部处理授权后发送，首条消息自动创建会话。
2. PDF 转图片并提取需求。已有明细且没有补充文字时直接复用，不重复发送图片识别。
   输入“继续”“继续查价”“重试”等完整执行口令同样复用已保存明细、价格关联和补全方案；后端也兼容旧页面误传替换标志的请求。有明细时，普通文字进入对话协作：解释不修改报价，“试试看”只读比较，“第3项改为5件”等明确指令生成新的待审核报价并展示差异，不重新识别整单。新增附件仍需明确确认整单重新识别影响；手动重新识别入口保留。
3. 模型使用 `search_prices` 自主搜索；根据结果改关键词、材质、状态或页码，不是写死的固定流水线。
4. `evaluate_price` 返回候选原始条件、标准价试算诊断和关联规则；标准价适用且工程量明确时可用 `select_price` 关联，仍通过现有严格校验。不能直接套价时自主提出有依据的 `complete_estimate` 暂估，不把标准匹配作为自主估价门槛。
5. `calculate_quote` 检查全部需求；`finish_quote` 仅在所有行可计价时生成草稿，单价与金额仍由程序确定性计算。
6. 由模型自主决定查价顺序、是否继续搜索、采用哪个依据和怎样估价，通过 `complete_estimate` 提交方案。未匹配、数量/尺寸不清晰或费用不全，由模型提出明确的暂定参数并在整单结束后列审核清单。现场口径的已确认边界由程序约束，其余不预设数量、费率、利润或来源优先级。原始字段不被覆盖，补全参数、依据、费用公式及范围单独保存。`read_requirement` 可读取压缩上下文中省略的完整依据和已保存方案。
7. 审核清单提供“修改并重新计价”：修改暂定值、原始需求或费用方案，一键保存并程序重算，无须再次调用模型；保留旧报价版本。批准前须明确确认补全参数、费用、范围及正式商业条款，不自动批准或发送报价。

历史会话可搜索、切换；手机上通过历史按钮打开会话列表。顶部固定显示排队、识别、计价、等待重试及人工介入状态，展示已计价数量和含暂估费用的小计。聊天仅展示报价摘要；审核区按模型估价、暂定数量、疑问或价格引用筛选，逐项展开原始值、采用值及费用依据。修改后可比较前一版项目金额和参数变化。工具诊断数据展开时单独加载。原有需求编辑、人工选价和手动计算入口保留。
输入框支持附件选择、拖入图片/PDF/XLSX、粘贴截图；Enter 发送，Shift+Enter 换行，中文输入法选词不触发发送。文字需求提取的 `text_evidence` 必须逐字来自客户输入，不能虚构文件来源。

### 自动计价边界

- 人工和历史标准价格路径保留类别、材质、厚度、工艺等原有校验。Agent 自主估价使用独立方案，不受这些标准匹配条件限制；适用判断和调整理由交给模型，结果交给人工审核。
- 原始数量未知仍保存为空；允许在补全清单中明确暂定数量，并用于总体待审核报价。原文明示值和人工补价始终优先，不能被模型估算覆盖。
- 费用来源分为报价库引用、历史案例引用和方案估价。库内/历史引用要求单价、编号及版本可核对，引用变化会使报价失效；纯估算不能伪装成供应商报价。材料参考不自动成为成品价格，成品方案须列出制作等费用及未包含范围。
- 现场口径的方案估价须填写 `rate_unit`（厘米、米、平方米、件、套、整项或比例）与 `expected_amount`（本项费用的独立校对金额，含工序难度，不是整行总价）。程序核对单位、工程量公式及校对金额，不通过时拒绝保存和整单交付；修改尺寸、费率、费用顺序或难度后须同步核对。库价已有建议加成不能在工程量里再次相乘，部件占比须用 `measurement_note` 说明，真实多部件分别列项。材料/成品的“0.1平方以下”档位不是最低计费面积，只有明确的背胶/裁形/3M胶外加工可以选最低面积策略。旧报价原快照保留，未通过新校验的报价标记失效，禁止批准和导出，须修正方案后生成新版本；以上校验不代表估算单价已获市场验证。
- 每项费用使用有限四则运算公式。尺寸、面积、字数、数量可联动；`unit_subtotal`、`fixed_subtotal`、`order_subtotal` 分别表示前序每件、整单固定和整单合计费用（含人工附加费），用于有依据的费用联动计算，现场口径排除税费等。新增 `letter_cm`、`billable_area_m2`、`character_count`、`power_units`。顺序可审核调整，每件费用禁止再次乘成品数量。审核保存代入算式、难度系数及计算前的参数快照。
- 未结构化规则和多候选选择必须列明暂定策略、适用条件和费用范围供审核，不能声称已执行通用规则或已人工确认。
- 现有导入的 2,803 条价格已按用户要求全部启用。仍保留原始单位、价格性质、备注及规格；复杂业务条件需进一步核实，不会仅因启用而跳过计价校验。
- 白名单工具无任意 SQL、文件访问、价格修改、规则启用、批准、外发功能。文件/报价库文字始终是数据。

### 执行与恢复

默认启用后台报价（`AGENT_BACKGROUND=true`），依赖 `REDIS_URL` 指向的 Redis。
启动接口提交任务后立即返回，页面每3秒单请求轮询轻量进度接口，仅传新增步骤，不重复下载配置、选项、全部报价和文件；任务结束时再加载完整结果。切换会话取消在途进度请求，关闭页面不影响后台处理。
每项估价先提交 PostgreSQL，再以版本和运行快照写入 Redis（`REDIS_PREFIX:job:<id>:revision:<revision>:run:<run_id>`），
包含原始需求、估算参数、费用明细、金额与审核依据。当前版本指针不会被较旧快照覆盖。
Redis 不可用时不继续计价；已提交的 SQL 记录保留，恢复后自动修复断点，不重复覆盖已完成方案。
Redis 服务自身的磁盘持久化由部署配置管理；应用不修改共享 Redis 的 AOF/RDB 设置，SQL 是恢复依据。
后台使用可续租的 Redis 锁防止多进程重复执行；服务重启后自动扫描未完成任务并恢复。
模型上下文包含当前未计费项目的完整资料、整单目录和已完成金额；保存一项后切换到下一项。
这只组织执行进度，数量假设、费用、单价和公式仍由模型自行提出，不预设业务参数。
全项目计费完成且模型调用 `finish_quote` 后才生成最终待审核稿，暂估金额参与总计。
关键条件无法合理暂估时，`defer_requirement` 保存具体原因、缺失字段及需客户回答的问题，暂挂该项并继续其余项目。后台 `ask_user` 兼容此行为，不再停住整单。缺客户资料、缺价格依据与执行异常分别标记；有合理依据的暂估仍走 `complete_estimate`，不能为凑完整报价猜造事实。其余项目完成后，仍有暂挂项则保存不可批准或客户导出的未完成清单，保留已计价小计，金额缺项不当作零。补充需求并确认修改后继续报价，不重做已完成项。
每项工作记忆保存在 SQL 的运行记录中，包含最近失败方案、修正字段及候选原始条件；调度续跑及手动重试会恢复与当前需求一致的记忆，需求变化则失效。相同项目、相同输入的同一工具调用连续重复时阻止再次执行，要求利用已有资料修正方案或明确暂挂。无进展时只重建一次修正上下文，避免每轮丢失新返回的工具结果。页面分别显示最近新增计价和最近工具调用。
临时模型异常采用30秒起的指数退避，最长900秒；默认连续5次重试失败后进入人工介入状态。认证、余额或无效请求等不可重试错误直接等待人工处理，不生成未完成报价、不标记成功。存储未恢复前不会启动模型计价。
手动停止仍有效；重新启动需再次授权。后台可能持续产生模型调用费用，可随时停止。
`AGENT_BACKGROUND=false` 仅保留原同步执行兼容模式，不提供后台自动续跑。

`agent_runs` 保存每次执行状态、工具参数/结果、token、追问信息。页面轮询进度，展开步骤可查看查价条件与返回结果。
识别失败单独记录 `extract_requirements_failed`，包含失败阶段、字段位置/页码（可获得时）、调用次数、token消耗及保留行数，不记录模型完整失败正文。继续执行的 `usage.reused_line_count` 记录复用明细数量，识别token为0；旧失败记录不会伪造补填未知诊断。
默认 `SOURCE_AGENT_ENABLED=true`，由 AI 调用原文/原图工具判断项目、数量、尺寸与跨文件关系，记录增删合并理由。初读按页/区域检查覆盖并批量保存结论，不逐项复查明确项目，也不强制第二遍通读；只有漏项、冲突、模糊或归属疑点才定向回看。每读 1–2 页或一小段表格先保存项目或页面笔记，后续按编号补充未知字段。上下文按轮重建，已消费原件最多保留两个阅读片段，同页分批保存项目时保留当前原件，保存页面笔记或覆盖结论后退出窗口；页面列表默认只列未读页，观察默认返回摘要，需要修订时按编号取完整内容。全部观察和笔记可分页重取。文本工作窗口软目标为 `SOURCE_AGENT_CONTEXT_CHARS=48000` 字符，不含图片用量或工具定义。后台分段自动续跑，默认每次启动或显式继续的总上限为 `SOURCE_AGENT_MAX_TOKENS=3000000` tokens、`SOURCE_AGENT_MAX_TURNS=1600` 轮，达到总预算才暂停并保留进度。续跑时恢复尚待处理的原图，已选价及人工项目保留。未读页面只能交付部分小计。阅读记录只证明实际提供过资料，不代表业务判断正确。

以下恢复流程仅适用于 `SOURCE_AGENT_ENABLED=false` 的兼容模式：两次格式修正仍未通过后进入资料恢复 Agent，通过 `read_extraction_source` 重读原文及原图、`repair_extraction_line` 逐项修正、`repair_extraction_batch` 修正顶层格式，仍走旧来源、数量、尺寸及项目覆盖校验。默认每批最多8轮恢复（`EXTRACTION_RECOVERY_ROUNDS`）。这不是默认 AI 核对模式的业务判断方式。
响应截断、工具数量超限、重复调用编号或参数JSON异常时，整轮不执行，记录不含响应正文的诊断及消耗，从已保存状态自动恢复。单周期连续3次响应异常后延后重试；跨周期累计6次后需要人工介入。工具schema错误返回字段路径及校验类型，不回显错误输入值。程序不会替模型调用 `finish_quote` 宣布完成。
查价每段最多 20 轮模型调用、60 次工具或 600 秒；达到单段执行预算时进入下一段。单段用量达到100,000 tokens或上下文达到60,000字符时仅压缩历史，不消耗执行段数，不因token用量暂停。压缩与恢复都携带程序复算的已计费金额和未完成项目。压缩仅在整批工具调用返回后进行，不产生缺失的工具响应。图片识别 tokens 单独统计。
搜索结果精简展示；`evaluate_price` 向模型返回完整候选条件和规则正文，原始工具结果保存在数据库审计记录中。搜索支持空格分词（AND）、工艺和备注匹配。

### 语义候选检索

配置硅基流动密钥后，报价AI可自主调用 `search_prices_semantic`，默认向量模型 `Qwen/Qwen3-Embedding-4B`；
原有 `search_prices` 关键词检索保留，不强制工具顺序，不自动采用相似度第一项。
候选包含编号、当前版本、单价、材质、板厚、规格、工艺、原始备注、来源与余弦相似度，
相似度不是适用性确认。由AI比较差异、决定进一步核对、引用或提出待审核估价。
缺少同材质/同工艺单价不能用近似结果冒充适用价格，最终仍由程序复算及人工审核。

右上角“模型配置”分为DeepSeek报价和硅基流动检索两个标签，两者密钥独立；配置接口不会回传密钥。
也可设置 `SILICONFLOW_API_KEY`、`SILICONFLOW_EMBEDDING_MODEL`、`SILICONFLOW_BASE_URL`、`SILICONFLOW_TIMEOUT`。
配置检索密钥后，AI调用语义工具会向硅基流动发送检索文字及报价库产品/材质/工艺/备注等文本。
不发送客户原文件或图片；不包含价格金额及来源文件名的向量文档。报价调用授权覆盖这些外部文本处理。
检索服务失败返回可恢复诊断，AI可继续关键词检索或估价，不因向量失败停止整单。

首次调用建立本地缓存 `.runtime/semantic-prices.sqlite3`，按服务地址、模型及文档内容指纹隔离，
切换模型不复用旧维度；语义字段变化仅重建变化文档，金额及版本变化无需重新向量化。
缓存只有报价库文本指纹与向量，不存密钥。每次返回候选重新读取数据库，语义内容变化或已停用项不返回，
最新价格及引用版本仍由计价程序检查。查询期间不持有任务行锁，停止或租约丢失不再写入任务结果。
向量用量独立记录于 `embedding_tokens`、`embedding_requests` 和步骤 `embedding_usage`，不伪装成DeepSeek用量。
在本机保留完整向量扫描，不增加数据库扩展或迁移，也不将业务数据写入外部向量库。

可在项目根目录运行 `.venv/Scripts/python.exe scripts/warm-semantic-index.py` 预热并只读验证；
`--configure-key` 通过隐藏输入读取密钥，仅在验证成功后保存到本机配置，不放入命令行参数或报告。

后台默认每6轮或90秒在完整工具批次结束后主动让出执行权，按最久未调度顺序继续其他任务；在途模型请求仍受模型超时约束。调度周期数不再暂停报价，`AGENT_MAX_CYCLES`仅兼容旧配置。`AGENT_MAX_IDLE_ROUNDS`（默认30）仅为提醒阈值；单项连续无可计价进展达到 `AGENT_STALL_ROUNDS`（默认12，最小6）时，保存诊断并以“执行受阻”暂挂，先处理其他项目，不认定客户资料或价格库一定不足。相同输入的同一工具第3次调用开始阻止重复执行。`AGENT_MAX_TOTAL_TOKENS`默认0，表示不设累计token上限，不因用量暂停；报价、识别及向量用量仍独立记录。只有显式设为正数时才启用累计报价用量保护，响应异常等执行保护仍保留。另可通过`AGENT_MAX_RETRIES`、`AGENT_SLICE_ROUNDS`、`AGENT_SLICE_SECONDS`配置。同步兼容模式保留8段、30分钟、160轮和480次工具保护。这些是执行保护，不决定业务价格。
模型检查点保留最近的精简搜索记录和当前需求最近一次核对结果；失败补全保留方案参数及诊断供模型修正，成功补全省略重复方案，大型失败方案只保留字段、费用和公式摘要。完整审计步骤仍保存在SQL。后台每轮刷新当前项目、候选及诊断，不携带其他项目的工具历史；按查价、方案编制、修正、交付阶段提供相关工具，V3后台只发送一份方案工具结构，避免预检与保存重复占用上下文。查到候选后推进方案编制；补查须填写 `missing_cost` 指出具体缺少的费用或费率，不能以修复计量缺项为由反复寻找描述完全相等的成品价。标准价不匹配时提供组合计价路径，材质、工艺和来源校验仍保留。单个字符字组的缺失宽高及计价长度可复用行级原始值或待审核补全，字组已有事实不覆盖，多字组不使用整行尺寸代替单字尺寸；厘米计价长度须显式提供，不由程序擅自按字高推定。模型自主调用 `finish_quote` 完成交付；同步兼容模式也可调用 `finish_pending_quote` 保存未完成进度。未知金额为 null，未完成总价为空，不允许批准或正式导出。

`preview_estimate` 本身只读。后台保留通过预检的完整方案及需求指纹，在下一次模型调用、执行预算检查和项目切换之前，通过原有 `complete_estimate` 校验并保存同一方案；单价或来源版本变化会返回修正诊断，不直接采用旧预检金额。保存独立记入SQL审计并发布Redis进度，仍须人工审核。旧任务中通过预检但未保存的方案，可在原始需求未变化时从审计恢复，不需要模型重新复制参数。单项token预算耗尽且已有候选或失败方案时，额外保留一次仅用于提交/修正方案的机会，不继续无目的检索。
V3组合方案必须以费用的 `target_id` 覆盖各原文部件；真正的整件成品价可用 `kind=finished`、`measurement=item_count/fixed` 及 `covers_component_ids` 明确覆盖。范围描述不能替代漏掉的部件费用，单项加工费不能冒充整套报价。缺项返回具体部件编号和方案修正诊断，未知金额仍为null。
停止立即标记本次运行失效，在途调用可能已产生费用，但其返回不再写入需求。服务器崩溃后在保护期结束可恢复。
继续操作会开启一个新运行，复用已保存需求、选价和补充历史，再重新查询验证，不重放旧的模型隐藏推理。
当前为API进程内后台线程配合Redis租约和SQL恢复，尚未引入独立队列worker服务；不能视为生产级无人值守调度系统。报价计算仍在每次检查点完整复核，审计仍使用`agent_runs.steps`；增量计价缓存与独立事件表需要单独迁移及依赖失效验证。

## 第二阶段使用

1. 在“客户需求”右上角的钥匙按钮中配置 DeepSeek API Key。默认模型 `deepseek-flash`，接口为官方 `/chat/completions`；配置保存不代表远端连接已验证。
2. 新建需求，上传 JPG/PNG/WebP、PDF 或普通 XLSX。PDF 上传只检查格式及页数并流式保存原件，预览按需生成；授权识别后在后台分批渲染和分块识别。XLSX 直接提取单元格和真实内嵌图片，无图工作表只发送文本；表格预览仅在打开时生成，不发送给模型，图纸可单独查看及缩放。
3. 手动模式点击“仅识别”，明确授权后才会将任务图片、历史需求及补充文字发送给 DeepSeek。
4. 核对 AI 的项目判断、来源、数量、材质、尺寸及工艺。可补充资料后重新识别，也可手工编辑。默认 AI 模式保留人工确认、已选价及已有费用方案；新增资料改变需求时旧报价失效。
5. 每项需求匹配价格，核对原价档位和相关规则，填写适用性依据。价格默认已启用，但仍需通过单位、价格性质、产品名称等计价校验。
6. 现场字类填写单字计价长度、每件字数或不同尺寸的字组；材料造型填写图纸面积或宽高。设置类型、难度、单双面、装灯及安装场景。费用按制作、加工、电源、支架等分类并填写依据，支持每件和整行一次。历史任务保留原计价方式。
7. 填写排除费用范围、有效期及显式选定的取整策略，计算草稿。存在阻塞时只显示已计价小计，不显示完整总价，也不能批准。
8. 审核并批准后导出客户版 CSV。内部成本、毛利、价格审核说明不进入客户文件。修改需求或相关价格会使旧报价过期，必须重新计算和批准才能再次导出。

### 模型配置与保护

- 可以通过 `DEEPSEEK_API_KEY` 环境变量/`.env` 设置密钥，也可以在页面中配置到 `.runtime/deepseek.json`；环境变量优先，页面不会返回已保存密钥。
- 基础 URL 和模型名只能从后端配置调整，浏览器不能提供任意远端地址。
- 模型输出必须符合 Pydantic schema，禁止额外金额字段；来源文件编号、页码、数值范围均校验。
- Excel、PDF及图片共用模型响应适配入口：仅转换含义明确的字段别名，例如整数字段`characters`转为`character_count`、可读文字转为`text_content`，字组内计数转为`count`。歧义值、字段冲突和未知字段保留交给严格校验，不直接忽略；字数不会变成成品件数。
- 格式修正携带完整的上次模型回答、具体校验位置、校验原因及字段说明，仅作为修正上下文，不记录完整失败正文。修正后检查项目数量及已有序号/名称，防止以删除或替换项目绕过校验；通过来源和数值校验后才保存批次。已有成功批次继续复用。
- 尺寸依据的数值为空时保留原始来源及待核实提示，不作为有效尺寸或图纸优先依据；无独立可读尺寸依据时清空对应主字段。畸形数值、多余字段和无效来源仍拒绝，持续字段错误的提示包含具体校验位置。
- 成品件数与长度/面积工程量分开：米、平方米等从真实数量/单位栏保留为原始工程量，不默认成1件。数量标注不清、小数或模型与单元格不一致时保留项目和原始依据，局部待核实不再中断整份识别；独立真实件数可恢复，真实冲突留空。错引其他项目、文件或页码仍拒绝。需求及报价明细显示工程量和具体数量疑点。
- 每个区域/图纸批次的格式校验最多修正一次；PDF输出截断立即细分该区域，避免原样重试。持续来源或格式错误停止自动重试，显示具体失败阶段。401及余额不足需人工处理；后台模式对限流、网络及服务故障有限退避重试，复用已保存的解析规划和批次。
- 后台PDF区域结果逐批存入SQL，完成的页面明细立即发布；中断、停止及重启后可复用已完成批次，不重复请求模型。原始需求作为识别输入保留在运行记录中。尚未全部识别的任务不能生成完整报价或人工覆盖明细；应先继续处理剩余页面。
- Excel 按实际资料行显示读取进度（含表头和说明行），区分读取单元格与核对内嵌图片。行批次完成后立即更新读取进度；对应预览分段全部校验、合并完成后发布明细，所以已读取行数不等于已保存项目数。恢复会复用成功批次及汇总结果，不重复累计数量或模型用量。图片读取失败仍保留资源审计与待核实提示，不当作已确认无图。
- 尺寸校验区分行首条目编号和紧接的小数尺寸（如 `2.0.5mm` 中的编号 `2.` 与厚度 `0.5mm`），保留原文并继续核验真实单元格引用。尺寸失败会返回具体项目、工作表、单元格、字段和依据索引，自动修复不得将其他正确尺寸误标为未知。恢复旧批次前先本地重新校验，已通过的批次无需再次请求模型；未通过的原因直接显示在聊天及进度接口。
- Excel 内容分流回归：`backend/tests/test_excel_content_routing.py`；桌面/手机界面回归：`scripts/smoke-excel-routing.cjs`（可用 `UI_BASE_URL` 指定前端地址，模型及 API 响应使用测试数据）。
- 请求超时默认 120 秒，可用 `DEEPSEEK_TIMEOUT` 修改；恢复保护期为两倍超时加 90 秒。
- 客户文件内容一律作为数据，不执行图片/PDF 内的命令或指令。所有提取结果默认未经人工核实；AI 形成业务判断，程序负责来源归属、存储格式、金额计算和审批边界。生成草稿不代表人工确认。

### Excel解析Skill

上传的 Excel 先由 AI 分析各工作表的结构和用途，再选择解析 Skill；同一工作簿可以混合不同类型。规划阶段只发送表头和少量样本，不先发送所有图纸。AI提出的表头行及字段地址必须存在于实际工作簿，不能用模板固定列位置代替来源核验。

综合描述列可同时映射材质、工艺、尺寸、备注等描述字段；产品、序号、数量和单位仍必须独立映射。规划修正会带上原响应及具体字段错误；两次尝试后仍不可信的列映射会被丢弃，改用内置逐单元格解析，并记录原因及覆盖复核提示，不按猜测列自动补项或补数量。工作表遗漏、未知方法、非法用途和损坏的响应仍停止，不猜测业务含义。自定义方法正文生成或保存失败、创建数量达到限制时，复用内置方法及已核验映射；网络、鉴权和限流保持原有重试策略。上述恢复均保留来源核验、实际调用用量及断点。

内置 Skill 位于 `backend/skills/`：图纸制作清单、工程量/需求清单、单价参考表、历史报价表、不规则布局，以及共同的来源安全契约。`SKILL.md` 使用 JSON 对象形式的 YAML frontmatter，加载器以标准 JSON 解析，避免引入额外 YAML 运行依赖。

现有方法不合适时，AI可创建解析方法，保存在 `.runtime/excel-skills/excel-generated-*/SKILL.md`，后续任务会将其纳入可选目录。生成阶段仅接收布局、语义字段和列结构，不接收客户原始单元格值、文件名或客户名称。生成方法通过类型、长度、路径与数量边界检查后加载为参考数据，不提升为系统指令，不执行脚本，不修改单价、业务规则、授权或批准状态；识别输出仍须通过全部来源和数值校验。自动创建每本最多2个新方法、库内最多32个，重复结构复用，避免无限生成及付费调用。

Skill选择和创建记录保存在任务步骤中，包含名称、来源和内容指纹。规划/生成用量累计入识别用量，成功规划和批次保存SQL断点；重新尝试相同输入时复用。单价参考表不会自动变成客户订购数量；费用摘要不当产品，明确成品数量可从真实数量/单位栏补回，米、平方米等工程量不改成件数。

### 文件与金额边界

- 默认单任务最多6份文件、合计500MB；单个PDF最大200MB，图片及XLSX最大20MB；图片/PDF合计最多500页，Excel自动分页不计入此页数限制；任务最多10000条明细。HTTP请求体允许任务容量加2MB表单开销。前端从`/api/upload-config`读取实际限制。
- 根据实际内容验证格式；接受普通 XLSX，不接收旧 XLS、宏 XLSM、GIF 动图或伪装的脚本文件。旧 XLS 须另存为 XLSX。图片解码限制为 2500 万像素。
- XLSX 不执行宏、公式、外部链接或嵌入对象；公式只保留原文和未验证缓存状态。压缩包最多3000个资源、展开不超过100MB、单项不超过32MB；最多2000行、60列、50000单元格。图纸无单页或整本张数限制，全部原图保留；概览只显示前6张缩略图以控制画布尺寸，每张图纸均可单独查看。识别根据图片字节量及批量大小自动分批，全部图纸都会处理，重复视图合并但不累加数量，冲突保留待核实。每页20个实际资料行，Excel自动分页无20页上限。仅读取可见表。来源校验覆盖工作表、单元格、文件及页码；识别明确表头的客户清单时补回漏项及原始类型/难度备注，其他布局提示人工核对。
- PDF后台每次至多预渲染4页，默认按上下两个区域独立识别，大幅面图纸自动增加行列分块。每块直接从PDF裁切渲染，最长边1800px，原文只读取对应区域并保留页码及归一化区域坐标；输出截断或区域原文过密时继续细分，深度上限默认3。重叠区域按原始项目序号及名称合并，数量不相加，冲突值留空并提示审核。较大图片也提供局部图，XLSX提供内嵌图纸原图。板厚与成品壳深 `depth_mm` 分开。有文本层时交叉校验尺寸；明确图纸尺寸及单位换算不会仅因文本层缺失而置空。复杂图纸仍需人工复核。

### 大PDF后台处理

升级后先在`backend`目录执行`../.venv/Scripts/python.exe -m alembic upgrade head`，再重启API。新增的`extraction_batches`表独立保存每个区域和整页的已校验结果；Agent运行记录只保存批次计数、进度及输入签名，避免把全部PDF批次反复写入一份运行JSON。

生产使用`AGENT_BACKGROUND=true`并保持PostgreSQL和Redis可用。“仅识别”和“Agent自动报价”都立即返回后台任务；后台在8个已保存批次或90秒后让出执行机会，只识别未完成区域，所有页面完成后才进入计价。界面显示已完成页数、已保存明细及当前区域，明细按每页50条展示。

容量、渲染批量、分块行列、细分深度及调度批量可用`.env.example`中的`MAX_PDF_UPLOAD_BYTES`、`MAX_JOB_UPLOAD_BYTES`、`MAX_JOB_PAGES`、`MAX_REQUIREMENT_LINES`、`PDF_RENDER_BATCH_PAGES`、`PDF_REGION_ROWS`、`PDF_REGION_COLUMNS`、`PDF_MAX_REGION_DEPTH`、`EXTRACTION_SLICE_BATCHES`配置。反向代理请求体限制和超时需与上传容量匹配；PDF页数、复杂度和模型响应速度决定总耗时，支持大文件不代表固定时间完成。

### 数据与计价校验

- 对可识别的编号表格，逐行核对原序号覆盖：漏项补回原文并标记待复核，同行不同尺寸置空并提示冲突，疑似把壳深当板厚也置空。此检查是保守兜底，不能替代对复杂图纸的人工验收。
- 上传资料位于 `.runtime/customer-files/`，预览、原始单元格和图纸 API 均要求管理身份，不暴露本地文件路径。删除会话清理关联资料，后台任务需先停止或恢复；尚无自动保留期限，上线前需确认保留策略。
- 所有金额使用 Decimal；每行先计算基础金额和附加费，再按分四舍五入，总金额汇总各行金额。
- 现场已确认的计价边界按版本约束；规格档位、未知工艺、最低面积范围、取整及毛利等仍需审核适用，不把未确认策略偷偷固化为通用规则。

### 跨类型通用报价

通用计价说明与维护规范见 [docs/generic-pricing.md](docs/generic-pricing.md)。新Agent费用方案和新建人工方案使用 `contract_version=2`，历史未标版本的方案继续按v1计算，不批量改价或覆盖旧需求。

费用支持整件、指定字组、指定部件三种对象，逐字、面积、长度、件/套、部件组合、工序/工时六类策略可以在同一项目混合。尺寸证据区分整体、单字、板厚、壳深、间距及局部；单词数不能冒充字符数。计价程序复核单价单位、独立校对金额、重复费用、部件用量和来源引用，模型不能直接指定总价。

价格编辑页可维护“单价已含费用”，保存在原价格属性中，不清空其他导入参数。修改触发版本更新及旧报价失效。未计价项目分别标记待客户确认、待管理员核价、执行受阻或尚未解决，分组问题数不当作未计价项目数；默认先修复已有资料和方案错误，不自动向客户追问。

识别纠错需原值和来源，原始需求不被覆盖；Excel文本纠错必须引用当前对象来源行中的真实单元格文字，PDF文本纠错必须命中文本层。图片引用仍需人工核对。已有人工确认或人工补价不会被Agent自动替换，所有暂定参数和估算价格仍须审核。

`QUOTE_ANOMALY_RATIO`（默认4）控制同类别/材质/厚度/费用单位的暂估费率差异提示，只是审核信号，不是市场价上限。

# 文件脚本工作区

### PDF、图片区域核查与多文件关联

PDF/图片默认增加独立区域巡视、疑似漏项局部重读和原图分块。多份附件全部处理后统一核对清单与图纸，明确唯一项目代码可合并证据，数量不相加；归属、未读清内容和冲突进入计价及报价审核。核查界面可打开原图区域，存在资料疑问时批准须明确确认资料完整性。配置、断点、用量及真实模型验收边界见 [PDF、图片与多文件报价识别](docs/visual-recognition.md)。
